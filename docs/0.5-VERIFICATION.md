## New behavior exercised

- Private rotation admits a retained verified neighbor and excludes a revoked fingerprint. A non-administrator cannot rotate; unverified retained identities block automatic redistribution, preventing fresh old-capability aliases from being silently retained.
- Tor rotation and durable delivery exercise the same application code while instrumentation forbids Direct/DHT/DNS actions. Old saved capability/state retires and old services are deleted.
- A peer mailbox delivers after the original sender exits. A restarted recipient suppresses duplicate delivery using its persisted ID/sequence state.
- A restarted sender retains its Ed25519 fingerprint, restores its durable outbox and retries through a supplied current seed using a freshly reserved sequence range.
- Saving an identity does not automatically enable durable sending or a mailbox. Live-only load is never retained in an enabled mailbox.
- Mailbox quotas reject excess unexpired work. Disabling a mailbox clears its records; expiry and backward-clock recovery do not resurrect expired records.
- Ciphertext/header tampering, wrong keys, unsafe permissions, symlink files, concurrent opens and unavailable key providers fail closed. New Noise keys accompany restored identities.
- Organization credentials require the exact trusted issuer, lobby, subject and import challenge. Tampering, wrong context, oversize data and invalid expiry fail. Organization labels do not create human trust or transfer to another lobby.
- Addressed durable/replayed bot prompts do not cross the provider boundary.
- Existing wrong-PSK, encrypted identity proof, wire confidentiality, ANSI/OSC sanitation, bounded authenticated flood and unwritable-HOME regressions remain passing.

A repeated gate run exposed a scheduling race between a stored-receipt UI event and the outbox disk commit. The event now follows the commit. Valid duplicate receipts can retry incomplete cleanup without redisplaying chat. The full default/all-feature gates passed after that correction.

## Practical limits

Mailbox receipts are peer assertions. No guarantee covers dishonest retention, all-member delivery, human reading or availability when holders/seeds are offline. Persistence commits before display favor duplicate suppression; a crash between those steps can suppress an unseen display. Old backups can roll sequence, expiry-floor and retirement state back. Revocation cannot erase old copies/forks or prevent a retained member leaking a new capability.

Organization credentials are optional attestations, not required-membership admission. Live XXC enrollment, issuer revocation directories, administrator recovery, multi-hour production soak and independent review remain future work. Arti stays experimental with the existing local patch and dependency caveats. Windows/macOS clients remain outside this milestone.

Release publication/signing and APT publication are separate from these source/build checks; building 0.5.0 does not update an already published release or the installed system package.
