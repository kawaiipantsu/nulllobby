## NullLobby 0.4.1 — Linux preview

This patch release packages the current Linux client and shared Rust core for publication and Debian installation. It includes the Linux TUI, theme and bot improvements from the 0.4.0 development preview; the version bump does not change the application protocol.

### Linux client

- Full-screen welcome, help, settings, notification and invitation overlays below the top menu, with a clean chat view by default.
- Copyable invitations using native terminal soft wrapping. Ctrl+Y explicitly requests clipboard copying through OSC 52; support and permission depend on the terminal. Invitations are never copied automatically.
- Compact bounded multiline paste with a preview. Slash-prefixed pasted lines remain chat; multiline lobby-card pastes are blocked from accidental broadcast.
- Optional timestamps, midnight separators, panel shortcuts, function-key menus, Nerd Font icons, five palettes and bounded irssi color/style import. Irssi templates, scripts and layouts are not imported.
- Opt-in saved appearance, nickname and public lobby bookmarks with autoconnect. Application identity keys, trust, private invitations and history remain in RAM. Saved nicknames and cards can correlate activity across restarts.
- Headless bots for loopback local models and explicitly enabled OpenAI or Claude APIs. Only addressed prompts reach the provider. Cloud bots are disabled in Tor mode; model output cannot execute application commands.
- README and wiki screenshots generated by the actual UI renderer using synthetic content.

### Packages and installation

The standard package supports Direct and external Tor. The separately named experimental Arti package adds embedded Tor and its documented local service-storage patch. Both install `/usr/bin/nulllobby`; choose one package. External Tor remains the default Tor backend.

```sh
sudo apt install ./nulllobby_0.4.1_amd64.deb
nulllobby --version
nulllobby --self-check
```

Packages target Linux amd64 with glibc 2.39 or newer. They include guides, example themes and dependency license notices. Both require certificate roots; Arti additionally requires `libsqlite3-0` for Tor's directory cache. No service, account, chat database or automatic launch is installed. SHA-256 checksums accompany each artifact set.

### Security and limits

Direct provides encrypted communications and exposes peer IP addresses. Tor uses onion services and never falls back to Direct; it cannot guarantee protection against a sufficiently powerful traffic-correlation observer. Tor cards need a reachable seed. Restart discards application identities, verification and chat history. Ordinary Tor guard/cache state is separate from application state.

Embedded Arti remains experimental, including the local patch that keeps onion service keys and replay state in RAM. Audit and dependency checks use documented advisory applicability and maintenance exceptions; see the [dependency assessment](https://github.com/kawaiipantsu/nulllobby/blob/main/docs/ARTI-DEPENDENCIES.md). No independent professional security audit has been completed.

Delivery acknowledgements, durable offline delivery, automatic NAT traversal, private capability revocation and Windows/macOS desktop clients remain deferred. Live paid-provider bot calls require operator credentials and were not exercised during development checks.
